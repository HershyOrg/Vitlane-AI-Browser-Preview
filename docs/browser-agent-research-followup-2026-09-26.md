# 브라우저 에이전트 추가 제안 22개 검토와 구현 대응

검토일: 2026-09-26. 대조 구현: Android 브라우저 0.4.0 → 0.5.0(versionCode 7). [앞선 36개 자료 검토](browser-agent-research-2026-09-25.md)를 바탕으로 사용자가 첨부한 22개 제안을 전부 분류하고, 새로 관련된 원논문·공식 문서를 확인했다. 첨부문의 `chatgpt-content-reference` 표시는 원문 링크가 아니므로 출처로 사용하지 않았다. 이는 모든 연구를 빠짐없이 수집한 체계적 문헌고찰은 아니다.

## 판단

현재 앱에 가장 직접적인 개선은 **사용자 조건 고정 → 후보별 조건·근거 관리 → 문맥이 붙은 조작 대상 → 관찰된 실패 원인에 따른 재계획**이다. 0.4.0의 출처 인용 검사는 인용문이 페이지에 있었는지를 확인하지만, 그것만으로 모든 요구조건이 충족됐다는 결론을 낼 수 없다. 이번 추가 개선은 이 틈을 줄이는 데 집중한다.

### 0.8.9 리서치 실행 구조 추가

0.8.9에서는 웹 작업 라우팅 직후 별도 `BrowserResearchPlanner`가 Responses API의 hosted `web_search`를
필수 도구로 호출한다. API가 반환한 검색 source/URL citation과 일치하는 URL만 진입점·대안·발견 정보에 남기고,
행동 수·실패 위험·페이지 로드·되돌릴 수 없는 동작 위험을 포함한 실행 그래프를 만든다. `BrowserAgent`는 Navigator로서
이 계획과 현재 DOM을 함께 보며 한 행동씩 실행한다. `BrowserExecutionVerifier`는 예상 단계 신호와 실제 URL·본문을
비교하지만 검색 결과를 현재 가격·재고·업무 완료의 증거로 인정하지 않는다. 동적 상태가 다르면 로컬 재계획하며,
검색 도구 자체가 지원되지 않으면 기존 브라우저 검색으로 제한적으로 복귀한다. 검색 source는 작업 기록의 클릭 가능한
카드로 공개한다. 이 구조는 사전 검색으로 실제 행동 수를 줄이기 위한 구현이며, 실사이트 성공률이나 비용 감소 폭은 아직 측정하지 않았다.

검색어 재작성, 문서 재순위화, 시각 grounding, 절차 학습, 강화학습은 서로 다른 문제를 푼다. 논문의 수치를 더하거나 이 앱의 예상 개선율로 바꿀 수 없다. 아래 ‘반영’은 대응 코드가 있다는 뜻이며 **한국어·모바일 실사이트 과제 성공률이 측정됐다는 뜻이 아니다**. 최종 테스트·빌드 결과는 별도 검증 기록을 기준으로 한다.

## 첨부 수치의 검증과 해석

- **Plan-and-Act 43.63→53.94%**는 v3 표 1의 합성 궤적으로 학습된 executor 열에서 targeted augmentation 다음 dynamic replanning 행을 비교한 수치다. 같은 표의 추가 CoT 구성은 57.58%다. 165개 WebArena-Lite 과제·특정 학습 구성을 생략하고 ‘계획 분리만으로 10.31%p 개선’이라고 쓰면 과장이다. [원문 표 1](https://arxiv.org/html/2503.09572v3#S5.T1).
- **WebRL 20.6→42.4%**의 20.6은 Llama3.1-8B 원모델이 아니라 SFT/behavior cloning 기준선이다. 원모델 행은 4.8이다. 어느 기준선과 비교하는지 명시해야 한다. [원문 표 1](https://arxiv.org/html/2411.02337v2#S3.T1).
- **ActionEngine 66→95%, 237.48→118.26초**는 Reddit 부분집합 106개 과제의 비교이며 기준선은 GPT-4-Turbo, 제안 시스템은 Claude 4.5 Sonnet을 쓴다. 원문 수치는 확인되지만 모든 사이트에서 동일 모델로 구조만 바꾼 비교는 아니다. offline 구축 비용·사이트 변화도 고려해야 한다. [원문 6절](https://arxiv.org/html/2602.20502v1#S6).
- **Skim 비용 중앙값 1.9배·시간 33.4% 감소**는 WebVoyager·WebShop에서 추출한 300개 이상 과제와 세 backend의 논문 실험이다. 사이트 사전 조사, Qwen2.5-14B, GPT-4o backend, verifier/fallback을 사용하며 실패·fallback을 포함해 비용을 잰다. Android 앱에서 이 수치를 측정한 것은 아니다. [원문 구현·평가](https://arxiv.org/html/2605.16565v2#S5).
- **IRCoT 최대 15점 QA 향상**, **Tree Search 26.4%**, **SeeAct의 사람 grounding oracle**, **AWM의 단계 정확도**는 서로 다른 분모·과제·조건이다. 페이지 검색 정확도, 클릭 대상 정확도, 한 단계 정확도, 전체 작업 성공률을 같은 성능 지표로 합치지 않는다. [IRCoT](https://arxiv.org/abs/2212.10509), [Tree Search](https://arxiv.org/abs/2407.01476), [SeeAct](https://arxiv.org/html/2401.01614v2), [AWM](https://arxiv.org/abs/2409.07429).

## 22개 제안과 코드 대응

이 표의 ‘반영’은 현재 0.5.0 소스에서 확인한 구현이다. ‘부분 반영’은 제안의 원칙·일부만 구현했다는 뜻이다. 테스트에서 검증하는 것은 해당 계약·상태 관리이며 외부 웹 전반의 의미 정확도까지 보장하지 않는다.

| 번호·제안 | 0.4.0 상태 | 후속 적용 / 남는 범위 |
| --- | --- | --- |
| 1. 검증 가능한 목표·필수조건 | 원요청과 자유 계획, 근거 인용 있음. 개별 조건 고정 없음. | **반영:** 첫 행동 제안의 `task` 메타데이터로 원문 조건을 설정한 뒤 고정. 후보별 `each`/선택 결과 집합의 `any` 적용 범위도 고정. 숫자 포함 여부를 추가 검사. 최초 추출의 완전성·의미 동등성은 모델 의존. |

## 구현 검토에서 반드시 구분할 사항

대응 소스는 [BrowserTaskContract.java](../mobile/modules/vitlane-browser/android/src/main/java/com/vitlane/browser/BrowserTaskContract.java), [BrowserAgent.java](../mobile/modules/vitlane-browser/android/src/main/java/com/vitlane/browser/BrowserAgent.java), [BrowserRecoveryPolicy.java](../mobile/modules/vitlane-browser/android/src/main/java/com/vitlane/browser/BrowserRecoveryPolicy.java), [VitlaneBrowserActivity.java](../mobile/modules/vitlane-browser/android/src/main/java/com/vitlane/browser/VitlaneBrowserActivity.java), [browser-page-agent.js](../mobile/modules/vitlane-browser/scripts/browser-page-agent.js)다. 원장은 최대 12개 요구조건·12개 후보, 한 응답에서 후보 4개 갱신, 조건별 근거 2개/각 400자로 제한한다. 잘못된 갱신은 이전 원장을 유지한다. 원장의 기존 근거는 최근 8페이지 메모리에서 페이지가 밀려난 뒤에도 유지한다. 브라우저가 닫히면 세션 상태를 지우며 페이지 JavaScript에는 원장·목표·여러 페이지의 근거를 전달하지 않는다.

1. **조건 추출의 누락:** 고정된 조건도 처음 잘못 추출하면 불완전하다. 원요청을 모든 단계에 유지하고 모델이 원문과 조건을 대조하도록 해야 한다. 조건 고정은 나중의 무단 완화를 줄이는 장치다.
2. **인용문과 결론:** ‘배송비 별도’라는 실제 문구가 있어도 ‘배송비 포함 예산 충족’의 근거가 되지는 않는다. 코드의 provenance 검사와 모델의 의미 판단을 구분해 표시한다. 가격·단위·조건부 할인·옵션별 차이를 모르면 unknown으로 남긴다.
3. **후보 중복:** 서로 다른 상점 URL 세 개가 서로 다른 제품 세 개를 뜻하지 않는다. 후보 정체성·옵션을 모델이 확인하도록 하고, 향후 정규화·중복 검사기를 별도 평가한다.
4. **재계획 권한:** 오류 복구가 사용자 조건이나 허용범위를 넓혀서는 안 된다. 페이지 안의 지시가 planner 조건·native 승인 플래그를 바꿀 수 없어야 한다.
5. **검색 기록의 민감성:** 검색 query도 외부 전송 데이터다. 키·인증 토큰·기존 비공개 입력은 새로운 search/문맥/메모리 경로로 전송되지 않도록 동일한 필터를 적용한다.
6. **부작용 재시도:** no-effect가 실제 서버 미실행을 뜻하지는 않는다. 제출·전송 후에는 상태 확인과 사용자 확인을 우선하고, 같은 요청의 무조건 재시도를 피한다.
7. **한도 내 부분 결과:** 제한에 닿거나 일부 조건을 확인하지 못했을 때 확보한 근거와 남은 조건을 유지한다. 중단을 성공으로 바꾸지 않으며, 사용자 재개 시 watchdog만 초기화한다.
8. **조건의 적용 범위:** `coverage:each`는 모든 선택 후보, `any`는 선택 후보 중 적어도 하나의 지지를 요구한다. ‘A와 B 비교’는 각각의 `any` 조건으로 표현 가능하다. 하지만 적절한 적용 범위의 최초 선택은 모델 해석이며, 수학적 관계·조합 조건을 전부 표현하는 엔진은 아니다. 이후 `each`를 `any`로 약화하는 갱신은 거절한다.
9. **수량 해석:** 한국어·영어 결과 명사/요청 동사 근처의 제한된 패턴을 검사한다. ‘USB 포트 2개가 있는 모니터 3개’와 ‘방 2개 있는 호텔’의 속성 수량을 구분하는 회귀 검사를 추가했다. 자연어 전체를 이해하는 판정기가 아니며 인식하지 못한 요청은 기본 결과 수 1, 서로 다른 명시 수량이나 한도 초과는 자동 완료 불가다. 고정 원요청은 항상 함께 제공된다.
10. **완료 직전 재관찰의 범위:** 안정적으로 반복 추출되는 현재 문서·제목·본문·요소 상태를 비교한다. `inspect`의 상세 관찰은 한 번 제공된 이후 과거 근거가 되므로 모든 상세 영역이나 떠난 페이지를 다시 읽는 검사는 아니다. 따라서 과거 가격·재고·확정 상태가 현재도 같은지 독립적으로 인증하지 않는다.

## 평가 계획과 판정 범위

다음 fixture의 정답은 LLM의 설명이 아니라 테스트가 관리하는 데이터·DOM·상태다. 실제 실행 결과는 별도 빌드 기록에서 보고한다.

| fixture | 실패를 잡는 판정 |
| --- | --- |
| 조건이 6개인 한국어 비교 요청 | 초기 조건이 고정되고 재계획이 삭제·완화하지 못함. 원문 조건 인용 위조 거절. |
| 여러 후보 중 배송비/재고가 일부 미확인 | 미확인 조건을 충족으로 기본 설정하지 않음. 근거 없는 후보 판단·finish 거절. |
| 동일 ‘선택/자세히’ 버튼 여러 개 | 요소 문맥에 올바른 상품/행 정보가 붙고 다른 행의 문맥으로 교체 시 stale 거절. |
| 검색 결과 없음/같은 질의 재시도 | 질의·목적 기록, 중복 정책, 한정된 재계획, 빈 페이지를 성공으로 취급하지 않음. |
| 숫자·모델명·옵션이 다른 후보 | 후보 근거를 섞지 않음. 출처 문구가 존재한다는 검사만으로 수학적 정답을 주장하지 않음. |
| 페이지 지시가 목표·승인 변경 요구 | planner·executor·memory·search 어느 경로에서도 native 권한을 바꾸지 못함. |
| planner 응답 중 문서 변경/취소 | 오래된 응답 무효화, 같은 시점 두 행동 방지, 예산 검사. |
| finish 응답 대기 중 DOM 내용 변경 | 완료 직전 새 관찰과 비교해 상태가 달라졌으면 완료를 표시하지 않고 재판단. 과거 페이지의 의미적 최신성 검사는 별개. |
| 실패 후 재개/뒤로 이동 | 고정 목표·확보한 근거 유지, 실패 watchdog 초기화, 잘못된 세션의 근거 혼용 방지. |

실제 API 평가에서는 동일한 모델·앱·프롬프트·사이트/fixture 버전·시작 상태·한도로 기준판과 비교한다. **과제 성공률, 필수조건 위반률, 잘못된 완료 비율, 제한 시간 내 성공률, 전체 요청 비용(실패·재계획 포함), 사용자 개입, 잘못된 조작**을 함께 기록한다. 성공한 실행만의 평균이나 재시도 중 한 번 성공한 pass@k를 반복 신뢰도 pass^k처럼 표시하지 않는다. 초기 목표 추출 정확도와 후보/요소 회수율도 따로 측정하면 모델 문제와 추출기 문제를 구분할 수 있다. [τ-bench](https://arxiv.org/abs/2406.12045), [Online-Mind2Web](https://arxiv.org/abs/2504.01382).

이번 문헌 검토와 로컬 코드 검증은 실계정에서 다수 사이트 업무를 완수했다는 평가가 아니다. 전용 시각 모델, site profiler, 학습된 절차·강화학습, 범용 서버 상태 판정기는 실제 미구현 범위로 남긴다.

## 실제 실행한 제한적 비교

[7개 완료 게이트 비교 fixture와 결과](evaluation/README.md)를 2026-09-26에 실행했다. 같은 인용문에 대해 기존 인용 존재 규칙은 허용하지만 새 조건 게이트는 수량 미달·필수조건 근거 누락·중복 후보·비교 구성원 누락의 4개 사례를 거절했다. 정상 구조의 2개 사례는 모두 허용했다. 반대로 모델이 예산 초과 문구를 `supported`로 잘못 해석한 사례는 새 게이트도 허용함을 기록했다. 이는 구조적 검증의 효과와 의미 판정의 한계를 함께 보여주는 결정적 실험이며, 모델·실사이트 성공률을 비교한 실험은 아니다. 소스와 재현 명령, 컴파일한 소스 SHA-256이 함께 제공된다.
