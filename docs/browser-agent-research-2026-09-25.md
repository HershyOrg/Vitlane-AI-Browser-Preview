# Vitlane Android 브라우저 에이전트 연구 검토와 개선 근거

조사 시작일: 2026-09-25. 구현 대조: 2026-09-26. 대상: `mobile/modules/vitlane-browser`의 Android WebView 런타임, 페이지 추출 스크립트, OpenAI 요청·응답 처리.

이 문서는 공개 원논문과 저자·제품의 공식 자료를 조사하여 **현재 앱에 옮길 수 있는 방법과 별도 연구가 필요한 방법을 구분**한다. 모든 관련 연구를 빠짐없이 수집했다는 의미의 체계적 문헌고찰이나, 논문 시스템 전체를 재현한 결과는 아니다. 2022–2026년의 관찰 표현, 조작, 계획·기억, 오류 복구, 결과 검증, 보안, 평가 자료를 폭넓게 살폈다. 앱의 구조에 직접 영향을 주는 자료는 본문·공식 API 설명까지 확인했고, 학습·모델 교체 후보는 원논문의 초록과 공개 설명을 검토했다. 검색 결과의 요약만으로 성능 수치를 채택하지 않았다.

## 핵심 판단

개선의 우선순위는 **관찰의 질 → 정확한 대상 조작 → 행동 결과 확인 → 작업 기억과 재계획 → 완료 근거**다. 권한을 더 주거나 매번 전체 HTML을 보내는 것만으로 이 문제를 해결할 수 없다. Mind2Web, Agent-E, D2Snap은 필요한 구조를 보존한 DOM 축약의 근거를 제공한다. ReAct, Avenir-Web, Wuying-Browser-Agent는 현재 상태·이전 결과·작업 상태를 연결하는 실행 구조의 근거가 된다. 이 판단은 연구 결과를 Vitlane에 옮긴 설계상의 추론이며, Vitlane의 실사이트 성공률이 이미 개선됐다는 측정 결과는 아니다. [Mind2Web](https://arxiv.org/abs/2306.06070), [Agent-E](https://arxiv.org/html/2407.13032v1), [D2Snap v4](https://arxiv.org/html/2508.04412v4), [Avenir-Web](https://arxiv.org/html/2602.02468v1), [Wuying-Browser-Agent](https://arxiv.org/html/2608.17319v1).

웹페이지의 코드도 두 종류를 구분해야 한다. 최초 응답 HTML은 실행 후 생긴 검색 결과·필터 상태를 놓칠 수 있다. 반대로 현재 DOM을 그대로 직렬화하면 스크립트, 스타일, 중복 메뉴, 개인정보와 불필요한 속성이 너무 많이 들어간다. 따라서 **현재 렌더링된 DOM에서 본문·제목·목록·표·폼 상태·선택지를 추출하고, 필요한 부분의 정제된 구조를 추가**하는 것이 이번 구현에 적합하다. 이미지나 캔버스의 내용을 이해하려면 별도의 시각 입력이 필요하다. DOM 방식만으로 그 기능을 갖췄다고 주장할 수는 없다. [Mind2Web 본문](https://arxiv.org/html/2306.06070v3), [VisualWebArena](https://arxiv.org/abs/2401.13649).

## 조사한 1차 자료와 적용 판단

날짜는 논문 최초 공개일이며, 중요한 최신 개정일을 병기했다. 공식 저장소·문서는 조사일의 공개 상태다. ‘채택’은 해당 설계 원칙을 현재 구현에 적용할 대상으로 선정했다는 뜻이며, 논문 전체의 재현이나 효과 검증을 뜻하지 않는다.

## 0.4.0 코드에 반영한 내용과 남은 차이

다음은 제안 목록과 구분되는 **실제 코드 대조 결과**다. 코드를 추가했다는 사실과 실사이트 성능 측정은 다르다. 최종 테스트·빌드 통과 범위는 빌드 보고를 기준으로 한다.

| 상태 | 방법 | 실제 구현과 범위 |
| --- | --- | --- |
| 반영 | 의미 구조 추출 | 본문 최대 10,000자, 조작 후보 최대 80개, 정제 HTML 최대 7,000자, 제목 구조·폼 요약·단일 select 선택지·선택 상태·뷰포트·DOM 변화 정보를 추출. `inspect(targetId)`는 해당 요소의 본문·HTML을 각각 최대 6,000자로 읽음. 전체 `outerHTML`이나 페이지 JavaScript를 보내지 않음. |
| 반영 | 일반 공개 필드 입력·선택·체크 | `type`, `select`, `check`를 모델/Java/DOM 도구 계약에 추가. 개인정보 입력란은 제외하며, 검색 외 입력·선택·체크는 native 확인창을 거침. 일반 입력은 자동 제출하지 않음. 체크는 원하는 상태 설정. `contenteditable`·다중 select·임의 키 입력까지 지원하는 것은 아님. |
| 반영 | 명시적 대기·뒤로 가기·부분 스크롤 | `wait` 250–5,000ms, `back`, 지정된 스크롤 영역의 `scroll(targetId)` 지원. 일반 `<a target="_blank">` 링크는 현재 탭에서 열지만 실제 여러 탭을 관리하지는 않음. |
| 반영 | 현재 관찰과 실제 대상 연결 | 문서 ID·URL·native 문서 세대·요소 지문·위치·활성 상태를 확인. 클릭/체크는 요소가 가려졌는지도 검사. 이전 문서 응답을 폐기하고 새 페이지를 읽음. 페이지 안의 DOM 코드이므로 격리된 브라우저 실행 환경과 같지는 않음. |
| 반영 | 준비 상태에 따른 재관찰 | `readyState`, `aria-busy`, DOM 변경 후 경과 시간을 사용. 조용한 상태를 기다리되 6초 이후에는 계속 변하는 페이지에서도 진행 가능. 이후 표시될 모든 콘텐츠의 완성을 증명하는 대기는 아님. |
| 반영 | 행동 후 변화와 복구 | [BrowserObservationPolicy.java](../mobile/modules/vitlane-browser/android/src/main/java/com/vitlane/browser/BrowserObservationPolicy.java)가 새 관찰에서 이동·체크/선택/입력 상태·기타 화면 변화를 확인. 변화가 불명확하면 잠시 재관찰한 뒤 `unknown`으로 피드백. 재계획과 반복 제한을 둠. `applied`는 관찰 가능한 변화이며 임의 업무의 완수 증명이 아님. |
| 반영 | 세션 작업 기억 | [BrowserTaskMemory.java](../mobile/modules/vitlane-browser/android/src/main/java/com/vitlane/browser/BrowserTaskMemory.java)에 최근 8개 페이지의 발췌, 최대 16개 출처 포함 사실, 최대 8개 남은 계획을 저장. 사실은 출처 URL과 관찰에 존재하는 근거를 요구. 모델 요약의 진위까지 보장하지 않음. 작업 중지·앱 복귀 후 이어서 사용할 수 있고 브라우저를 닫으면 삭제. 디스크에 영구 저장하지 않음. |
| 부분 반영 | 완료 조건과 근거 | 모델에게 모든 목표 조건과 행동 후 결과를 확인하도록 지시. `finish`에 1–6개의 URL·근거 발췌를 요구하고, 근거가 현재/저장 관찰에 없으면 `inspect`로 전환. 이는 출처 존재 검사다. 별도 의미 판정기·사이트 서버 상태 판정기·각 조건의 강제 체크리스트 상태 머신은 구현하지 않음. |
| 반영 | 반복·실행 한도·취소 | native 반복 행동/진전 없음과 메모리의 정체를 감지. 기본 20단계·300초를 유지하며 설정 범위를 최대 100단계·1,800초로 확장. 사용자 터치·앱 이탈·중지 이후 늦은 모델 응답은 무효화. 사용량 기반 금액 한도 계산은 별도 구현하지 않음. |
| 반영 | 결과·작업 기록 표시 | 한 줄 상태와 별도로 스크롤 가능한 작업 기록·결과 창 제공. 제목은 ‘AI 결과와 페이지 근거’이며, 브라우저가 임의 업무의 완료를 독립적으로 인증했다는 표현을 사용하지 않음. |
| 부분 반영 | 메뉴·동적 공개 UI | 후보 역할과 `summary`·탭·선택지·메뉴 항목 등을 확대. 검색 외 버튼의 native 확인은 유지됨. 의미 분류만으로 모든 일반 버튼을 자동 허용하는 정책은 적용하지 않음. |
| 로컬 검증 완료 | 정상 동작·보안·native 통합 | DOM fixture, JVM planner/memory 계약, native 관찰 정책, Android 빌드로 계층별 확인. 실계정 API 호출·여러 상용 사이트 end-to-end 평가와는 별개. |

새 구조는 **목표·메모리 → 현재 페이지 관찰 → 다음 행동 → native 확인·실행 → 새 관찰과 변화 검사 → 메모리 갱신**이다. Avenir-Web의 학습·복수 모델·시각 grounding 전체, AWM의 재사용 절차 학습 전체, Wuying의 모델 학습을 구현한 것은 아니다. 현재 가벼운 구조에서 검증 가능한 실행 원칙을 적용했다.

## 이번 경량 실행 구조와 따로 검증할 항목

모든 방법을 동시에 추가하면 유용성이 커진다고 뒷받침하는 연구는 없다. 다음 항목은 현재 코드에 작은 수정으로 동일하게 구현할 수 없거나, 필요한 검증 없이 켜면 잘못된 작업을 늘릴 수 있어 후속 범위를 명시한다.

| 항목 | 필요한 추가 작업 | 채택 조건 |
| --- | --- | --- |
| 스크린샷·시각 grounding | WebView 캡처, 계정·입력값 마스킹, 이미지 API 입력, 좌표와 문서·뷰포트 매핑, 시각 행동 검증 | 텍스트로 해결 불가능한 과제에서 측정 가능한 개선. 캡처 정보 유출·잘못된 클릭 회귀 없음. |
| cross-origin iframe·closed shadow DOM | DOM 접근 제한과 별개인 시각·플랫폼 입력 경로 필요 | 출처·세션·허가 경계를 지킨 통합 테스트. 보안 제한을 해제하는 방식으로 우회하지 않음. |
| 여러 실제 탭과 창 | WebView 세션·활성 탭·문서 세대·팝업·뒤로가기 상태를 관리하는 런타임 | 잘못된 탭에 입력하거나 종료하지 않는 Android 테스트. 일반 링크를 현재 탭에서 여는 개선과는 구분. |
| 파일 업로드·다운로드·OS 전체 조작 | 문서 선택기, 파일 출처·대상 확인, 별도 권한과 결과 전달 설계 | 사용자가 맡긴 작업에 필요한 범위와 결과를 검증할 수 있을 때. |
| 영구 절차 학습 / AWM | 성공한 실행의 신뢰도 판정, 절차 버전·사이트 변경·개인정보 수명 관리 | 검증된 절차만 재사용하고 삭제 가능. 현재 세션 메모리와 구분. |
| 복수 전문 모델 / 모델 자동 교체 | 모델별 요청·출력 계약, 권한·비용·성능 측정 | 현재 사용자가 설정한 `gpt-5-mini`를 임의로 바꾸지 않고 비교 선택 가능할 때. |
| MCTS·다중 병렬 시도 | 복제·초기화 가능한 사이트 환경 또는 읽기 전용 탐색 한정 | 실제 주문·전송·예약을 여러 번 실행하지 않음. 성공률과 비용을 함께 평가. |
| 강화학습·전용 모델 | 라이선스·데이터·학습 환경·추론 서버·오프라인 평가 | Wuying·WebSailor·MolmoWeb 논문의 모델을 프롬프트 수정만으로 구현했다고 주장하지 않음. |
| 서버 내부 API·네트워크 응답 활용 | 사이트가 지원하는 API·연동 권한·스키마·세션 경계 | DOM으로 없는 정보를 무조건 쿠키와 함께 가져오는 기능은 도입하지 않음. 공개 API가 허용되면 별도 구조화 도구가 될 수 있음. |

로그인된 페이지를 읽는 기능, 일반 폼 입력, 최종 제출은 서로 다른 권한이다. 작업에 필요한 기능을 구체적으로 늘리는 것이 적합하며 Android의 연락처·파일·접근성 권한을 포괄적으로 추가하는 것은 현재 WebView 문제의 해결책이 아니다. 페이지 안의 지시·HTML·검색 결과는 사용자 승인으로 취급하지 않는다. [OpenAI 공식 실행 지침](https://developers.openai.com/api/docs/guides/tools-computer-use), [WASP](https://arxiv.org/abs/2504.18575).

## 검증 계획

로컬 fixture는 외부 사이트나 실제 사용자 계정을 변경하지 않고 브라우저 동작을 재현한다. 정답은 모델의 완료 문구가 아닌 테스트가 관리하는 상태로 판단한다. 이 계획 자체는 실행 완료를 뜻하지 않으며, 실제 통과 항목은 빌드·검증 보고에 별도로 기록한다.

| 시나리오 | 결정적 확인 기준 |
| --- | --- |
| 검색 → 결과 → 상세 2개 → 비교 | 두 상세 페이지의 사실과 URL이 세션 기억에 남고 비교 입력에서 모두 확인됨. |
| 일반 폼, select, checkbox, radio | 입력·선택한 실제 DOM 값 일치. 이미 체크한 항목에 다시 같은 상태를 요청해도 반대로 바뀌지 않음. |
| React류 controlled input | native setter와 이벤트 처리 후 읽은 값이 요청한 값과 일치. 값이 되돌아가면 성공으로 기록하지 않음. |
| 늦게 표시되는 결과·hydration | 초기 빈 관찰을 완료로 간주하지 않고 제한된 대기 후 변경된 내용을 사용. |
| SPA URL 변경·일반 페이지 이동·리다이렉트 | 이전 관찰 대상이나 늦은 모델 응답을 실행하지 않음. 목표·근거는 새 문서에서도 유지. |
| 가려진 버튼·disabled 필드·교체된 요소 | 조작 거절 또는 재관찰. 다른 요소를 잘못 누르지 않음. |
| 클릭 이벤트는 성공했으나 결과 변화 없음 | 실행 요청 전달과 결과 관찰을 구별하고 같은 무효 행동을 무한 반복하지 않음. |
| 검색 결과 아래 긴 본문·표·목록 | 페이지 앞부분 제한으로 필요한 영역이 영구 누락되지 않으며 구조·내용의 제한이 일관됨. |
| `finish`에 근거 없음 / 관찰에 없는 근거 | 그대로 완료 처리하지 않음. 관찰된 문구와 허가·목표 충족을 혼동하지 않음. |
| 페이지·라벨·메모리의 지시 주입 | 지시를 권한으로 승격하지 않음. 모델이 승인 플래그·스크립트·미등록 도구를 반환해도 실행하지 않음. |
| 개인 입력·토큰·민감 URL | 관찰과 요청에 제외·차단 규칙이 적용됨. 기존 값이 HTML 속성·폼 상태로 우회해 전송되지 않음. |
| 터치·백그라운드·취소·시간 초과 | 뒤늦은 네트워크·JavaScript callback이 행동을 실행하지 않음. |
| 느린/거절된 API 응답 | 모델 부재·형식·키·할당량·네트워크 오류를 구별하고 새 모델로 몰래 전환하지 않음. |

실제 API를 이용한 다음 평가에서는 모델 ID, 프롬프트 버전, 앱 버전, 사이트·과제 버전, 시작 상태, 실행 한도와 시도를 고정해야 한다. 최소한 **단일 시도 과제 성공률, 잘못된 완료 선언 비율, 잘못된 조작 비율, 사용자 개입 횟수, 평균 단계·시간·토큰, 복구 성공률**을 기록한다. 반복 시도 중 한 번 성공한 비율과 단일 시도 성공률은 따로 보고한다. Android 실기기/에뮬레이터의 WebView 결과를 데스크톱 Chromium 결과와 섞지 않는다. [Agent-E](https://arxiv.org/html/2407.13032v1), [Online-Mind2Web](https://arxiv.org/abs/2504.01382), [AndroidWorld](https://arxiv.org/abs/2405.14573).

## 소스 확인 기록과 해석 주의

- 중심 구현 근거는 원문을 확인했다: Mind2Web v3, SeeAct v2, Agent-E v1, Avenir-Web v1의 방법·실패 검증·구성 요소 제거 실험, Wuying v1의 실행 엔진 절, D2Snap v4. 나머지 논문은 원논문의 공개 페이지·초록 및 필요시 연결 본문을 선별 검토했다.
- 프레임워크 비교는 공식 BrowserGym·AgentLab·Browser Use·WebArena-Verified 저장소와 공식 API 문서를 사용했다. 별도 순위 사이트·재작성 블로그·SNS 수치를 성능 근거로 쓰지 않았다.
- D2Snap은 2025년 검색 요약과 2026년 개정의 수치·통계 표현이 달랐다. 이 문서는 최신 v4의 제한을 기준으로 해석했다.
- 초기 WorkArena 자료의 과제 수와 개정 자료의 과제 수가 달라질 수 있다. 이 문서는 당시 숫자를 현재 앱의 커버리지로 환산하지 않았다.
- 모델·벤치마크·관찰 방식·도구·시도 수·사이트 버전이 다르면 논문의 성공률끼리 직접 우열을 정할 수 없다. 이 조사에서는 수치를 합산하거나 예상 성능 개선율을 계산하지 않았다.
- 실제 웹페이지 조작, 로그인 계정에서의 작업, 비용을 발생시키는 API 평가를 이 문헌 검토만으로 완료했다고 볼 수 없다.
